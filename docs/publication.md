# 公开内容检查

## 纳入仓库

应用源码、测试、构建脚本、版本锁文件、词库及许可、CI 工作流和使用文档适合公开。`manifest.json` 中的应用 ID 是平台公开标识，不是认证凭据；保留它可复现同一上传包。源码 URL、公开账号名和提交号同样是发布信息。

## 排除内容

`.gitignore` 排除以下内容：

- `.env`、环境专用配置、私钥和日志。
- `node_modules/`、`.cache/`、覆盖率及临时输出。
- `dist/` 和 `output/`，包括打包文件、测试截图及其中的临时密码。
- `branding/` 中未被页面使用的原始标志素材。
- `vendor/sdk/` 中未附许可证的上游 SDK 副本。

官方 SDK 仓库在固定提交 `acbe7817a006bd82c2fc084611d8f43de245808c` 未附许可证，本仓库不转载该副本。开发环境仅下载并验证官方打包工具，运行时直接使用社区提供的接口，详见 [开发文档](development.md)。

提交使用 GitHub 的 noreply 邮箱，避免将个人邮箱写入公开历史。不要将浏览器导出的 Cookie、论坛调试日志、认证令牌、生产密码或用户提供的附件加入仓库。

## 发布检查

发布前检查暂存区和新增文件，运行测试、词库重建检查及构建。版本核验只处理公开源码和固定构建产物，不采集页面密码、用户资料或浏览器存储。安全边界和完整包比对方式见 [安全设计](../SECURITY.md) 与 [发布与核验](releases.md)。
